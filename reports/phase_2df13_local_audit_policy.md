# Phase 2D-F13 — fitting-only local-audit authorization

## Scope and authorization

This policy governs **only** an export of the 675 approved fitting patients' original 20,530-gene expression rows. It does not authorize final-model fitting, full-source/test access, or final-test evaluation. Each real extraction requires a new, explicit human approval naming the reviewed Git revision and a canonical UUIDv4 attempt ID. The operator records that approval outside the output directory and places its reference in the fixed Git-ignored `final_fit_v1_authorization.json`. The local record is operational evidence, not a cryptographic signature or an independently administered ledger; the code cannot authenticate the person named by the reference.

The exact `final_fit_local_audit_v1` record binds the attempt ID, approval reference, clean Git revision and repository root, canonical absolute output path, frozen configuration and split SHA-256, recorded source and verified schema identifiers and hashes, ordered fitting patient/sample and gene digests, and `final_fit_v1`. Old authorization schemas and extra or missing fields are rejected. Before claim creation, the exporter independently re-derives the frozen 506 train plus 169 validation population, excludes 169 test patients, verifies metadata, and rechecks the record and revision. A fixed ignored marker contains the authorization-file checksum and those provenance bindings.

## Local attempt and recovery

The attempt marker is exclusively created before source values or output creation; the output directory is also exclusively created. On Windows, `CreateFileW(CREATE_NEW)` supplies a protected DACL at creation granting the current user, SYSTEM, and Administrators, with no inherited grants. The same open handle is used to write and flush marker bytes, read them back, verify the DACL, and obtain its volume serial and 128-bit file ID. After closing this exclusive handle, a fresh handle to the fixed path must report the same identity. Unsupported identity queries, path substitution, or ACL failures stop the export and retain any visible claim. Other users without those rights cannot ordinarily edit it; the same user and administrators still can. The creating handle must close before the independent path open, so a same-user replacement after that comparison remains outside the local audit control.

File-content flushing and write-through are used but **do not prove the marker directory entry survives a power loss**. The policy does not claim globally enforced single-attempt execution. If a process fails before the marker becomes visible, a launch may remain uncertain. A visible marker, partial output, failure record, or ambiguous crash is never automatically deleted or retried. The operator must inspect the authorization, marker, output state, manifest, and independent approval record, document the outcome, and give fresh explicit approval with a new attempt ID before any repeat. The sealed artifact, manifest, success marker and payload are verified before the terminal `completed` event is appended. The independent completion verifier then requires the exact state sequence, matching hashes, and absence of failure or pending files. A crash after appending `completed` but before the caller receives success can leave an apparently complete artifact; the operator must reconcile that ambiguous outcome before any further approval. A power loss can still leave filesystem state uncertain.

The exact-range reader, original float64 byte copying, one source descriptor, source identity checks, two selected-row digests, and `final_fit_v1` manifest remain unchanged. Recorded full-source hashes are not freshly verified during export; full-source SHA-256 and exact fitting-row source-value comparison remain deferred to separately authorized test access. Storage read-ahead cannot be ruled out at the hardware/OS level, while the application requests only fitting-row byte ranges.

No scientific model parameter, frozen membership, Phase 2B/2C result, or final-test guard changes under this policy. A fitting-export record cannot satisfy the separate final-test authorization schema, and the real final-test executor and test-access stage remain disabled.
